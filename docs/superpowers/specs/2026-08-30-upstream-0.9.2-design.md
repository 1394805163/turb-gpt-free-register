# 上游兼容优化 0.9.2 设计

## 目标

吸收 `myfanhua/turb-gpt-free-register` 上游截至 `79087b7` 的低风险改进，同时保留本分支已有的 iCloud、CloakBrowser、Resin/Mihomo、OAuth、OTP 重试和任务看门狗实现。

## 范围

### 账号 2FA/TOTP 筛选

在现有账号 API 和现代/旧版账号页增加 `totp_status` 查询参数。筛选值包括：

- `enabled`：存在 `totp_secret`；
- `disabled`：不存在 `totp_secret`；
- `pending`：`totp_setup_status` 为 `queued` 或 `running`；
- `failed`：`totp_setup_status` 为 `failed`。

后端使用当前 JSON 文件存储和 Python 过滤实现，不引入上游 SQLite JSON1 重构。账号列表和套餐状态快照使用同一筛选结果，切换筛选时清空当前页选择并回到第一页。

### 延迟邮箱领取

自动邮箱模式下，注册任务准备阶段只生成姓名和生日，不领取邮箱。CloakBrowser 与 BrowserUse 在确认页面出现可见邮箱输入框后才调用邮箱分配器，并通过回调把实际邮箱写入任务记录。固定邮箱模式保持原行为。协议/非浏览器入口因没有可等待的页面，仍在真正开始认证前领取邮箱。

### 性能兼容

保留当前分支已有的静态查看页防抖、JSON API 压缩和前端轮询降频。仅核对上游行为，不合并会替换运行时存储、注册平台或部署结构的提交。

## 错误处理

- 页面未出现邮箱输入框时不得消耗邮箱池素材；任务失败且没有生成账号时回收已领取素材。
- 邮箱分配器返回空值时立即报告明确错误。
- 无效的 TOTP 筛选值按具体状态值匹配；空值表示不过滤，保持旧 API 兼容。

## 验证

- 后端定向测试覆盖四类 TOTP 筛选、快照筛选和空值兼容。
- 注册分配定向测试覆盖页面确认前不领取、确认后领取、固定邮箱不重复领取。
- 运行定向 `unittest`、`compileall`、`git diff --check`，再执行 CodeGraph sync/status。
